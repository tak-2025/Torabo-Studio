# Torabo Studio

リポジトリ名は `Torabo-Studio`（ハイフン区切り）ですが、製品としての表示名は
**Torabo Studio**（スペース区切り）で統一しています。

**[torabo-tsuki](https://github.com/sekigon-gonnoc/zmk-keyboard-torabo-tsuki-lp) 向けに機能拡張した [ZMK Studio](https://github.com/zmkfirmware/zmk-studio) の非公式フォーク。**

**→ <https://tak-2025.github.io/Torabo-Studio/>**

インストール不要。**Chrome または Edge** で開くだけで使えます。

> ⚠️ 本プロジェクトは ZMK Project とは **提携・承認関係にありません**。ZMK Studio
> （Apache-2.0）を改変した非公式版です。問題報告は本リポジトリへお願いします。

ZMK Studio のキーマップ編集機能はそのままに、torabo-tsuki のトラックボール・トラックパッド・
エンコーダ・LED・タップ反応（Hold-Tap/デバウンス）・マクロ・コンボを **再フラッシュせず
BLE / USB 経由でライブ編集**するためのタブを追加しています。

## はじめかた

1. **キーボードを準備する。** キーマップ編集だけなら、そのままで使えます。
   トラックボールなどの独自設定タブも使いたい場合は、
   [torabo-tsuki_ext_FW](https://github.com/tak-2025/torabo-tsuki_ext_FW) のスニペットを含めて
   ビルドしたファームウェアを書き込んでおきます（同リポジトリの README に手順があります）。
2. **接続する。** 画面の **Bluetooth** または **USB** を押し、一覧から自分のキーボードを選びます。
   - Windows で Bluetooth のとき、**接続中のキーボードは一覧に出てきません**。
     [下記の手順](#-windows-のブラウザ版における制約)で一度だけ一覧に出す必要があります。
   - **USB でも独自設定を編集できます**（`torabo-rpc-tunnel` 対応ファームウェアが必要です。
     非対応の古い FW では、USB はキーマップ編集のみです）。
3. **編集する。** 接続すると、そのキーボードが持っている機能のタブだけが表示されます。
   左のレイヤー一覧から編集したいレイヤーを選び、キーをクリックして割り当てを変えます。
4. **保存する。** 変更したら **保存** を押します。押した時点でキーボード本体に書き込まれ、
   すぐ反映されます（再フラッシュは不要です）。
5. **バックアップを取っておく。** 「バックアップ」タブから設定一式を `.json` 1ファイルに
   書き出せます。設定を作り込む前後で取っておくと安心です。

各タブの詳しい使い方は [docs/](docs/) を参照してください。

## ZMK Studio からの追加機能

| タブ | 内容 |
|---|---|
| **キーマップ** | ZMK Studio 標準のキーマップ／レイヤー編集（上流機能そのまま） |
| **トラックボール** | レイヤー/軸ごとの move・scroll・速度、temp-layer（オートマウスレイヤー）を BLE / USB でライブ設定。慣性スクロール（滑走の長さ・開始しきい値、デバイスごと）にも対応 |
| **トラックパッド** | レイヤー/軸ごとに カーソル移動・スクロール・エンコーダ風スワイプ・タップ/2本指タップ/ホールド等のジェスチャを BLE / USB でライブ設定。慣性スクロール（滑走の長さ・開始しきい値、デバイスごと）にも対応 |
| **エンコーダ** | ロータリーエンコーダの回転（CW/CCW）にレイヤーごとの behavior を割当。音量等のプリセット＋任意キー割当 |
| **LED** | 左右それぞれの LED を「条件（レイヤー/モディファイア/用途）→ 色・点灯パターン」のルールで設定 |
| **タップ反応** | Hold-Tap（`&mt` / `&lt`）の判定時間（tapping-term など）とキースキャンのデバウンス時間を BLE / USB でライブ設定。分割対応ファームウェアなら左右両半身に反映 |
| **マクロ** | `&dmac` ダイナミックマクロを BLE / USB でライブ編集（NVS 保存、再フラッシュ不要）。`keymap.keymap` からの取り込みにも対応 |
| **コンボ** | キー位置の同時押しで behavior（kp/mo/to/tog/&dmac）を発火するコンボを BLE / USB でライブ編集（NVS 保存、再フラッシュ不要） |
| **バックアップ** | 各種設定・マクロ・コンボ・キーマップを1ファイル（.json）にエクスポート/インポート。`keymap.keymap` 形式での書き出しも可 |
| **日本語 UI** | ヘッダーの言語トグルで 日本語 / English を切替（i18n） |

### 接続したキーボードに合わせてタブを出し分け

torabo-tsuki のファームウェアはスニペットの組み合わせでビルドされるため、キーボードごとに
搭載機能が異なります。本アプリは接続時にファームウェアへ**機能記述子**を問い合わせ、
**そのキーボードが実際に持つ機能のタブだけ**を表示します（例：エンコーダ非搭載ならエンコーダ
タブは出ない、LED がどちらの半分にも無ければ LED タブは出ない）。この記述子を持たない古い
ファームウェアでは、従来どおり全タブを表示します。

また、ファームウェアが本アプリの知らない新しいワイヤ形式を報告した場合は、書き込みで設定を
壊さないよう**そのタブを読み取り専用に切り替え**、アプリ更新を促します。

これらのタブは、対になるファームウェアモジュール
**[torabo-tsuki_ext_FW](https://github.com/tak-2025/torabo-tsuki_ext_FW)** が公開する
カスタム GATT サービス、または同じワイヤ形式を Studio RPC に載せるトンネル
（`torabo-rpc-tunnel`）経由で通信します。BLE では GATT サービスへ直接、USB
（トンネル対応ファームウェアの場合）では RPC トンネル経由です。ライブ編集を使うには、
そのモジュールを含めてビルドしたファームウェアが必要です。

## 動作環境

- **ブラウザ版**: <https://tak-2025.github.io/Torabo-Studio/> — インストール不要。Chrome / Edge のみ
  （Safari / Firefox は Web Bluetooth / Web Serial 非対応）。
- **デスクトップアプリ**: Tauri 製。Windows / macOS / Linux。BLE・シリアル（USB）両対応。
  **ビルド済みバイナリは配布していません**。必要な方は fork してご自身でビルドしてください
  （下記「開発・ビルド」）。CI（`.github/workflows/build.yml`）が作る成果物は開発時の動作確認用の
  ビルドであり、リリース物ではありません。

### ブラウザ版でできること

| 接続 | キーマップ編集 | トラックボール等の独自設定 |
|---|---|---|
| USB（Web Serial） | ⭕ | ⭕（要トンネル対応 FW） |
| Bluetooth（Web Bluetooth） | ⭕ | ⭕ |

トンネル（`torabo-rpc-tunnel`）対応ファームウェアなら、USB でも独自設定が届きます
（デスクトップ版でも同じです）。届かない接続（非対応の古い FW で USB 接続した場合など）では、
該当タブを自動的に非表示にします。

### ⚠ Windows のブラウザ版における制約

**PC と接続中のキーボードは、ブラウザの機器一覧に出てきません。** ブラウザは「見つけられる状態」
の機器しか列挙できず、ZMK は接続中は見つけられる状態になりません。この抜け道である
`navigator.bluetooth.getDevices()` は Edge 151 時点で未実装です。

接続するには、一覧を開いた状態でキーボードを一度見つけられる状態にします（アプリ内にも手順を
表示します）:

1. ブラウザ版で「Bluetooth」を押して一覧を開く
2. キーボードのプロファイル切替キー（`&bt BT_SEL`）で別のプロファイルへ切り替える
3. 一覧に出てきたら、**いつも使っているプロファイルに戻す**（戻さないとキーボードを操作できません。
   一度出た機器は戻しても選べます）
4. 一覧から選んで接続

必要なのは接続時の一度だけで、繋がればセッション中はそのまま使えます。プロファイルの追加消費も
ありません。Linux / ChromeOS ではこの制約はありません。

なお、デスクトップ版はこの制約を受けません（OS のペアリング済み一覧から直接開けるため）。
Windows でこの手順を毎回踏みたくない場合は、自分でビルドする価値があります。USB（Web Serial）
接続にはこの制約はありません。

## 開発・ビルド

```bash
npm install

# Web 開発サーバ
npm run dev

# デスクトップアプリ（開発）
npm run tauri dev

# デスクトップアプリ（配布ビルド）
npm run tauri build

# UI コンポーネントカタログ
npm run storybook
```

Rust ツールチェーン（Tauri 用）と Node.js が必要です。デスクトップの BLE 接続は
ネイティブ実装のため、上記「Windows のブラウザ版における制約」の回避手順は不要です
（OS のペアリング済み一覧から直接接続できます）。
